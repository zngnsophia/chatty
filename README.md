# Мини-мессенджер

Минималистичный веб-мессенджер с регистрацией и авторизацией по логину и паролю
и одним общим чатом в реальном времени.

## Возможности

- Регистрация и вход по логину/паролю (пароли хешируются, `bcryptjs`)
- Сессия хранится в httpOnly-cookie с JWT — не нужна база данных для сессий
- Общий чат в реальном времени через `socket.io`
- Список участников, которые сейчас онлайн
- История последних сообщений подгружается при входе
- Данные пользователей и сообщений хранятся в JSON-файлах в папке `data/`
- Минималистичный интерфейс без внешних UI-фреймворков

## Стек

Node.js, Express, Socket.io, JWT, bcryptjs — всё на чистом JS, без нативных
зависимостей и без базы данных, поэтому проект запускается сразу после
`npm install`.

## Запуск локально

```bash
npm install
npm start
```

Приложение будет доступно на [http://localhost:3000](http://localhost:3000).

По умолчанию сервер сам генерирует секрет для JWT при первом запуске
(файл `data/secret.key`, не попадает в git). При желании можно задать
свой секрет и порт через переменные окружения:

```bash
PORT=3000 JWT_SECRET=your-secret-here npm start
```

## Структура проекта

```
server.js              — Express-сервер, API, Socket.io
public/
  index.html            — страница входа / регистрации
  chat.html              — страница чата
  css/style.css          — стили
  js/auth.js              — логика формы входа/регистрации
  js/chat.js               — логика чата (сокеты, история, отправка сообщений)
data/                       — users.json и messages.json создаются автоматически
```

## Публикация на GitHub

```bash
git add .
git commit -m "Initial commit: mini messenger"
git branch -M main
git remote add origin <ссылка на ваш репозиторий>
git push -u origin main
```

Папка `data/` с реальными данными пользователей и сообщений в git не
попадает (см. `.gitignore`) — на новом сервере файлы создадутся заново
при первом запуске.

## Возможные доработки

- Личные сообщения между двумя пользователями вместо одного общего чата
- Аватары и статус "печатает…"
- Хранение данных в полноценной БД (PostgreSQL/SQLite) вместо JSON-файлов
- Смена пароля и удаление аккаунта
